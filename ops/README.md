# 当前交付工具

完整状态优先级、场景矩阵、慢回升和重启合同见[温控策略矩阵](thermal-policy.md)。策略规格由`thermal_policy.policy_spec()`提供，API和页面使用同一份参数。候选实现与实际部署版本必须分开核验。

唯一离线入口是根目录 `check.py`。`release_index.json` 列出当前文件及所有必跑套件。旧 R3、R5 原生发布脚本和试验锚点保留历史身份，当前入口不能执行它们。新发布须使用本次授权和确切候选清单；历史入口不能复用。

## 执行完整离线检查

使用 Python 3.12 创建 `.venv-check`，再安装根目录 `requirements.txt`。必须安装 Node，UI 检查不允许静默跳过。

Windows 执行：

```powershell
.\.venv-check\Scripts\python.exe -B check.py
```

Linux 执行：

```sh
.venv-check/bin/python -B check.py
```

检查包含应用、历史无回滚契约、当前启动证据、观察器和交付检查。每套使用独立进程。报告和完整输出保存到新建的 `.audit/check-<id>`。Windows 成功返回 `offline_pass_native_pending`。ARM/Linux 原生检查成功仍显示实机验收待完成。`--require-native` 在非 ARM/Linux 返回非零，不授予原生证明。

Windows 应用测试入口模拟目录 fsync，报告明确列出该适配；生产目录同步保护不变。原生持久化和权限测试按具体测试 ID 跳过，其他跳过或整套没有实际执行测试均不能通过。Linux 不使用该模拟。

修改文件后，先审查差异，再显式运行 `check.py --refresh-inventory` 更新候选清单，最后重新检查。更新清单不授予测试通过、部署成功或实机验收。`--suite` 只用于定位，部分套件通过不是完整检查。

本地 Git 已保留改造前源码快照。`.private`、运行状态、隔离环境和历史审计批量文件均不跟踪。仅离线回归必需的少量历史文件显式跟踪。Git 使用 `.githooks/pre-commit`，提交前自动运行统一检查。CI 配置也运行同一入口。CI 未在远程平台执行，普通 Linux CI 不等于 ARM 实机验收。

提交检查在测试前后核对暂存区和工作区的全部清单文件，拒绝提交未被检查的另一份内容。新克隆需运行 `git config core.hooksPath .githooks` 启用本地钩子。

## 读取运行状态

默认报告的安装、进程、准入、控制、UI 和历史状态均是 `unknown`。离线测试不能改变这些字段。指定 HTTPS 入口及已核实的 PEM CA 文件后可以读取公共状态：

```sh
python -B check.py --status-url https://192.168.3.180:8910 --ca-file verified-public-ca.pem
```

TLS 校验保持启用。该命令只发送 GET，不携带账号、token 或控制命令。页面返回正常只证明接口响应。公共状态不能证明安装文件哈希、PID、启动准入或实机验收，它们仍为 `unknown`。观察器的写入计数也只标为 `writing_reported`，不能冒充独立核验的连续采集。

## 查看当前候选

`ops/startup_evidence` 包含 R6 已验证的失败证据保存。集中版测试继续验证原拒绝帧和尝试累计值能够保留，写入或关闭失败不能报告验收成功。`fixtures/original_verifier.txt` 仅用于离线提取原判据，不能作为原生入口。`phase_replay.py` 验证完整历史与稀疏观察可能出现计时分歧。它不是原实时故障证明。原 30 秒和 6 秒限制保持不变。

`ops/observer` 保留只读观察能力。独立观察历史明确标注 `source=observer`、`control_active=false`、`learning_eligible=false`，不能作为控制或学习验收结果。观察目录与正式状态不重叠，切换控制服务后仍保留原有观察记录。

## Docker 自动控制

`ops/docker/compose.yaml` 的控制容器复用当前 `service.py`、完整控制页面、设置 API 和控制历史。生产入口使用纯规则温控，学习与学习阈值应用均暂停。根文件系统只读，正式状态是控制器唯一的可写业务目录。独立诊断目录保存监督退出证据。准入目录只读，必须包含当前 `release_index.json` 的 SHA256、原状态目录 dev/inode 和 `natural_load_continuous` 授权；准入不接受旧 R3/R5 试验记录。

`controller_supervisor.py --preflight` 只读核验全部源文件、TLS、凭据格式、已保存设置、电机预算、保留学习文件的目录结构与占用及 `Journal.index_ready`。失败不启动控制器、不重置预算、不修复历史。有效的故障预算保留，由现有控制器通过真实匹配读回和可靠持久保存恢复。

电机第二次尝试后，迟到的读回若确认已保存阶段档位、开机、favorite 模式和正转速，也可解除该阶段的内存锁定。阶段确认不等于当前请求已完成，后续仍按原调速间隔和持久预算逐步执行。读回未知、不匹配或预算持久化异常不能借此恢复；磁盘保留原尝试债务，直到下一次指令先可靠保存新的预算。本段描述候选代码合同，不证明该候选已部署或实际风机已恢复。

已知的存储、设置、配对或记忆准入阻塞，在预留新的电机尝试前返回，不改变尝试数或调速时间。预留之后才出现的阻塞仍由最终提交入口拒绝，并保留已预留的债务。该顺序修正不退还历史债务，不解除既有故障，也不把收藏寄存器当作真实档位。

### 旧版故障记录退役

2026-10-20候选将旧版永久故障与当前未确认指令分开。仅身份正确、格式有效且`version=1 / attempts=2 / fault=true`的历史预算进入一次性退役路径，不再被当作当前永久故障。加载和监督预检不修改原文件。退役前仍须经过原启动观察间隔、当前完整新鲜的四机温度证据、低于80°C、健康存储和记忆准入，以及收藏模式、正转速和0至16档的直接读回。只读确认既有高档不授予高风写入权限，也不改变普通10档上限；否则会形成必须先降档才能解除旧锁、却又被旧锁挡住降档的循环。条件不足时保持只读，不盲目切模式或调速。

退役先可靠归档原始字节、来源元数据和SHA256，再可靠写入新版预算。来源变化、归档冲突或持久化不确定均停止本次操作。新版预算和随后产生的未确认指令跨重启保留，不能再次按旧故障清除。旧版一次未确认指令和损坏、不安全或身份不符的文件同样不能借此重置。退役本身不发送设备指令，后续调速仍须新的持久预留和最终准入检查，温度保护及原电机间隔不变。

本段描述候选合同，不证明已部署或风机已恢复。旧故障证据保留，不删除日志、凭据或学习状态。此前一次最多60秒、两次尝试的现场恢复授权不因该迁移自动扩展。

2026-10-20补充的目标是服务启动即接管收藏模式，由软件自动温控调档，不交给米家auto模式决定风量。该启动接管尚未实现。首次bootstrap-2草案因可能降低既有散热、采样换代导致预设后锁定及最终入口时效缺口被独立复核拒绝，未发布，已从工作源码撤除并单独保留。后续实现必须先准备合适预设并读回，再申请favorite，不能激活遗留16档；也不能忽略当前温度、存储、设置、原截止、电机债务或不确定发送。auto下的收藏寄存器不是实际定档端点，故障锁不能由启动或匹配寄存器自行解除。

监督进程使用私有 Unix socket，只接受实际子进程 PID 的 READY/WATCHDOG 消息。保留原 40 秒健康超时和 35 秒保护退出，Docker 停止宽限为 45 秒。失效时结束当前子进程并保存独立证据。Docker 使用 `unless-stopped` 重启同一准入新版，每次重新预检；不会回到旧代码或检查点。容器或宿主整体冻结不在内部监督器的检测能力内。

发布前必须在确切镜像内运行完整 `check.py --require-native`，并通过独立审查和正式状态只读预检。之后禁用旧 systemd 控制器、停止并排空观察器，检查 8910 已释放及原状态独占锁可用，才启动固定 image ID 的控制容器。历史准入保持 blocked，不能用来启动旧宿主服务。实际运行验证页面文件、进程、独占锁、自动设置、连续控制历史、传感器及真实风机反馈。

保存 `manual_level=null` 表示自动模式。`control_mode` 报告已保存方式，`control_active` 报告控制处理是否新鲜，`fan` 单独报告实际执行结果。`history_recording` 只在原始日志追加完成后递增，学习检查点失败不会撤销已完成的原始记录。自然负载持续控制与压力验收分别报告。

固定规则使用一个工作状态，区分散热需求、下一允许档位和真实读回。普通上调每次最多两档，两次实际上调至少间隔十秒。执行器在所有请求合并和持久预算重算后再次执行限制。电机尝试至少间隔八秒，真实下降至少间隔三十秒，未知实际档位禁止盲写，正 RPM 匹配读回才能确认。

负载达到30%或功率达到80W时，启动一次负载预备，需求最多为周期起始实际档加两档。逐机器负载跨度不超过5个百分点、功率跨度不超过max(10W,原基线10%)且持续安全可比60秒后，预备结束并撤销其需求下限与禁降条件。稳定负载按至少8°C同源预测余量重新评估下降。低负载60秒结束周期。真实负载改变和温度风险可重新取证，但不补回温漂额度。

全部同源温度完整覆盖后，自动模式的普通下降每次只降一档，先取得至少一百八十秒连续合格观察；每次真实正转速确认新档位后，重新取得完整观察窗口。空闲须预测目标余量至少5°C，非空闲须至少8°C；某个来源正在升温且该来源自己的预测余量不足8°C时保持，不把冷传感器的微小升温与另一平稳传感器的余量拼成全局升温条件。待确认下降使用同一同源判据。观察区间的起点、终点均须合格，重复新鲜读回保留已有信用但不增加时间，下一份推进读回最多增加三秒。待执行时间不累计下一次下降信用；真实缺口、来源变化和不匹配撤销信用。无法证明下降风险有界的不确定性仍撤销信用，不把旧观察时间跨越不合格区间累计。手动及显式关闭高风门控的历史兼容模式不套用此自动单步策略。这些时长是保守工程初值，不是已校准散热响应。

固定自动模式分别保留原始保护证据、普通调控证据与下降风险判断。原始实温、快速危急预测、缺失传感器外推、存储与通信安全锚点、高风授权和失败档位记忆不使用普通噪声豁免。低风险且工况可比时，普通预测要求同一来源的持续趋势支持，三个短时上涨样本不能单独外推三十秒后就证明需要10档。平稳噪声可被识别；未确认升温不能据此记为散热失败，也不能仅凭“趋势未确认”永久阻止有充足原始余量的单步下降。实际超过工作目标或原始保护触发仍立即处理。普通证据分别与所属DGX的身份、真实风机档位、负载及功率绑定，另一台机器的空闲波动不取消该来源的比较窗口。不可比来源回到原始判据，重新覆盖后才使用普通噪声识别，不放宽原始判据的工况范围。仅分类窗口重建不撤销仍满足下降风险判据的连续观察；真正不合格的起点或终点不能累计时间。反馈报告保护中断或读回失败时冻结下降并撤销资格，恢复后的首帧不补计中断时间。该修改属于候选代码合同，不证明已部署或更低档位已通过实机验证。

低风险准入要求完整新鲜同源温度、已核实身份、正转速端点及相应预测余量。稳定负载结束预备后可以取证，不再永久被30%或80W门槛阻止。可信端点可以是严格匹配读回，或已有NoAscent验证的高档退出端点；旧请求过期不把已知实际档位变成未知。当前精确下降边仍核验原端点和原截止，不能顺带准入下一次下降。

下降风险保留同源原始、未限幅的30秒估计，并结合完整60秒稳健斜率的180秒外推。安全慢回升要求逐来源余量至少8°C、斜率不超过0.01°C/s、没有快速持续升温或扩张波动且累计温升额度未耗尽。已完整证明的安全平稳往返波动独立分类，不把其短窗口上行阶段直接当作持续漂移；仍检查完整窗口实际峰值、当前未限幅预测及同源余量。累计额度跨档位、工况与重启保留；耗尽暂停下降但不写热失败。同一确认档位和本机可比工况下，来源自身完整180秒安全新平衡可重新建锚，要求整窗无正漂移且末段中位数不高于首段；无关来源的波动不清除这项恢复证据。最终执行仍须全部必需来源合格，过去拒绝的时间不追认信用。详细边界见[温控策略矩阵](thermal-policy.md)。这些是工程风险判据，不是已标定预测保证。

观察合格与立即执行由同一逐源风险结果区分为拒绝、仅观察和可执行。六秒内至少2°C的正向跳温仍须通过上述原始余量判据才能计时。陌生跳温仍等待跳温后三十秒完整覆盖；只有本来源已证明重复回归的低风险波动，才不再无限重开全局禁降门。短窗口证明要求六十秒完整覆盖、范围不超过2°C、稳健斜率绝对值低于0.01°C/s、当前温度回到先前窗口范围，且有重复上涨回落或完整平坦证据。另一分支从本档一百八十秒历史推导至少两次不重叠完整回落、范围不超过2°C和稳定六十秒分块，仍先检查真实持续升温与扩张范围。正常工况分类窗口重建不把物理档位历史重置，但身份、实际档位变化、真实缺口、存储暂停或保护中断会使其失效。所有来源均须合格才执行，每次新实际档位重新观察。连续信用最多保存到所需时长，不跨不合格区间积攒。待确认下降遇到请求时刻之后的新跳温仍取消许可；真实目的档位若已在同帧确认，按已发生的运动处理，重新观察且保留原保护边。

待确认的精确下降边可以按相同原始判据重新核验，不代表准入下一次下降，不积累下一档观察时间，不更换原六十秒执行截止。实际确认新档后重取完整一百八十秒观察；旧档原始温度历史不被宣称为新档散热响应证据。所有原始危急预测及其他保护保持独立。

普通试降后同源实测温度达到工作目标减2°C，或同源持续实测回升超过2°C且实温严格超过工作目标减5°C，恢复该下降边先前实际确认的安全档。仅预测达到原恢复阈值而实测未满足上述条件时，暂停下降并重新取得完整观察窗口，不据此确认散热能力不足、不留下失败档位下限。高档退出边使用下述独立监测合同，不因仍高于普通工作目标而自动判失败。保留下降边，使随后真实升温仍能精确恢复安全端点。普通需求上调、危急温度和其他保护继续独立评估。这是暂定工程策略，不是经过实机标定的预测保证。

恢复不会叠加普通预备10档。真实失败档及更低目的档保持阻止，按机器与来源身份保存。另一机器变空闲、换到另一身份、安全档吹凉或仅时间经过均不删除原失败。原身份再次出现时恢复限制。康复使用失败来源自身的负载和功率改善，通常须负载降低15个百分点、功率降低20%，原低负载小于15%时允许负载不高于原值且功率降低20%，再取60秒完整安全证据，之后仍重新取得普通下降资格。缺失身份不冒充替换。热记忆与未完成下降已接入可靠快照门控，重启不复用信用、权限或旧截止。详见[持久状态与重启](thermal-policy.md#失败记忆保存和重启)。

`strategy_mode=rules` 和 `learning.enabled=false` 表示纯固定规则。学习文件按原字节保留并计入容量；存储、设置和停机不更新学习文件。生产不训练、不评估、不发布学习参数。显式关闭 high_wind_gate 的历史兼容测试保留原行为，生产默认开启。

近期跳温的逐源恢复证据分为完整60秒、范围不超过2°C的历史，以及跳温之前已经建立且当前仍有效的完整升温回落范围。后一种证据不回填过去的合格秒数，恢复边界不得早于证明建立。周期内上行相位与基线漂移分别计算；当前未限幅30秒预测、冻结峰值及至少8°C余量仍独立核验。完整180秒原始历史的非正漂移、首末中位数和峰值余量继续约束额度恢复，不能把当前拒绝或仅观察提升为可执行。新峰值突破、持续升温、身份或反馈中断仍拒绝下降，待确认新跳温取消规则不变。详见策略矩阵中的因果记录合同，不能据此保证每个低温时段下降。

负载已经结束时，使用独立的60秒空闲退出资格，不再要求所有传感器连续没有短时跳温。必须有推进的匹配正转速读回、完整身份和传感器、原始预测至少8°C余量，且没有功率、通信或温度保护异常。退出预备清零下降信用，随后仍重新取得普通180秒观察；持续负载的预备结束条件没有放宽。

### 通信和高风授权

跨机器时间使用统一的保守时效合同。采集端原始 `source_ts`、本机收到数据的墙钟 `sampled_at`、请求开始的单调时钟 `requested_mono` 均保持原值。暂定跨机时钟不确定性预算为正负0.5秒，这是工程假设，不是NTP同步标志证明的误差上限，也不是采样周期。该预算计入数据年龄，不能把六秒有效期延长到六点五秒。超过未来时间预算、真正过期、原始时间重复或倒退、身份异常仍保留保护。

同一份原始时间证据只推导固定的保守单调观察时刻。重复评估、页面查询、权限发布和执行前复核都不能把观察时刻向后移动或延长原截止。候选发布前还须直接读取四台采集接口，使用确切候选的规范化与准入判据验证两轮推进数据；旧版公共状态的宽松时间判断不能代替候选准入。此处描述候选合同，离线通过不证明已部署或已发生真实降档。

只有明确传输失败能使用短暂通信宽限。节点与风机同时失联时保留此前完全健康的锚点，任一通道恢复或状态读取不能单独续期。风机第三次失败或原锚点满十五秒提高保护需求，三十秒是外界限；节点原九秒、十八秒分级保持。实际未知仍未知，执行器不盲写。格式、身份、存储、预算和电机故障不能借用宽限。恢复不留下无理由的永久10档保底。

enhanced80-r4候选延续普通增强档80°C准入。可信CPU、GPU与受保护板级最高实温不足80°C时，普通有效需求至多10档；达到80°C才有资格使用11至16档，仍须通过动作和预算检查。80°C不是器件安全上限，原60/65°C工作目标和75°C风险信号继续独立保留。功率、预测、旧容量不足、手动16和旧安全端点标签不能单独越过门槛。

单有80°C普通资格不能把实际10档直接请求为16档。增强区按已确认端点逐档增加；来源故障保护和真实失败的精确恢复另行呈现，不标成普通逐档退出。

已在11至16档时，完整可信低温与真实favorite正转速端点可以规划`ceiling_exit`，每次只降一档至10。没有失败阻塞时不再等待旧180秒观察、工作目标余量、负载可比窗口或温漂债务。有相关历史失败时保留记录，使用当前真实端点和完整同源可比工况重新核验60秒，只取得本步相邻退出资格；请求10而实际16本身不取消取证资格。普通工作目标附近的小幅回温不再直接判高档退出失败，11到10仍保留高档边监测。八秒尝试、三十秒真实下降、两次尝试预算、固定六十秒截止及当前确切持久意图仍须满足。未决实际执行、损坏或饱和记忆、未知反馈、预算和存储异常仍可拒绝下降。退出不产生学习收益，不清空历史限制。详细时序、R3历史边界和R4候选持久化约束见策略矩阵。

R4候选将本步重新取证分为有界空闲工况和严格可比工况。空闲要求每台CPU和GPU负载均不高于15%、功率严格低于80W，完整身份和来源不变；范围内波动不因超过原5个百分点或10W而反复撤销窗口。离开空闲、来源、端点或失败证据改变仍重新取证。已确认危险必须先满足原负载或功率改善要求，再以完整60秒温度窗口判断，不再由任意一次正温升单独清零。持续升温、原始温度和预测门槛、波幅、斜率及首末中位数条件保留。页面与历史区分取样不足、工况变化、改善不足和温度窗口拒绝，60秒到时不等于获准下降。

新增直接观测的危险来源保存在原热记忆的可选`ceiling_dangers`表，与已有失败行及当前意图一起可靠保存。旧失败行不改写，不推断其原始危险原因；新事件使用自己的实际基线，不能误用占用同一档位的旧失败基线。重启恢复新危险的限制，不恢复信用和动作权限。本段是候选合同，不证明已部署或实际档位已下降。

来源故障和真实可归因试降失败分别使用窄保护证明，不伪造80°C。来源故障证明只接受当前必需温度源的缺失、过期、拒绝、身份歧义或时间错误；失败恢复只回到该边已确认的必要安全端点。普通存储等待、预测和高功率不能变成通用16档例外。所有保护仍受真实反馈、电机和可靠保存约束。最终同步设备提交与当前快照发布有序核验，预算保存后权限失效不能继续写。

普通上限10、本步指令15和实际16是不同字段。实际临时高于10可能处于受控退出或真实保护阻塞，页面必须给出具体原因，不得把请求成功当作物理完成。纯规则、七天日志、学习暂停与原设备凭据保持。完整合同见[高档逐级退出](thermal-policy.md#高档逐级退出)。这里描述候选合同，不能单凭文档声称已部署。

#### R1历史高风合同

以下五段仅用于解读旧记录与保留的旧下降证据，不是enhanced80-r2正常增强授权或门槛退出的准入规则。

普通、手动和非温度保护请求默认封顶10档。CPU与GPU工作目标60°C、其他保护传感器65°C、危急线75°C均为暂定工程值，不是厂家额定极限。ACPI仍是待核实的CPU保护代理。当前可信同源实温达到危急线即授予短期保护权限，不等待容量观察；另一节点失联不取消这一独立证据。来源时间、身份和实际温度随不可变权限发布，六秒整到期，执行器写入前使用同一验证合同复查。

权限API保留旧四参数构造的兼容语义：省略proof使用显式MeasuredCritical默认值，仍须实测至少75°C及完整时效验证；显式传入proof=None无效，不能代替危急证据。危急和实测不足权限只允许保持或受限上升，高档下降必须另有绑定精确下降边的NoAscent权限；安全恢复只允许恢复精确端点。

实测增强须有完整新鲜同源温度、正转速匹配的实际10档、可比负载及功率来源。请求10档不能代替实际读回。暂定观察180秒，见证传感器每次都须高于工作目标加1°C，覆盖的早晚温度块中位数不能显示至少0.5°C恢复。明确降温、低于工作目标或仅负载高都不能证明10档不足。重复读回不增加信用，每次最多增加三秒，缺口不能补时，工况范围始终与原窗口比较。

首次合格只请求11档，开启固定600秒实测周期。首次确认11档不撤销该周期。之后每个实际高档须重新取得60秒可比响应，原见证始终高于工作目标加1°C且无明确恢复才可再加一档。降温或仅剩小于等于1°C的残差保持当前档，全部保护温度低于工作目标减2°C持续60秒结束增强需求。每份权限仍最多六秒，正常可写上限只支持当前下一步，通信或存储保护合并不能借此请求16档。来源、身份、工况中断或固定截止使证书退役；新的普通增强周期须重新观察实际10档。没有已标定验证的预测路径。

撤权、证据缺失或周期到期不会授权实际16直接降至10。未知实际保持只读，已知运行高档可在没有写入的情况下保持。新鲜正转速实际读回与先前已确认的安全端点一致，且完整新鲜温度安全时，可取得禁止上升的安全退出权限。读回因已撤销目标而显示pending不妨碍这种物理证据，但不确认旧请求。自动高档退出从11至16每次仅降1档，最低到10，先取得完整60秒本档趋势，再累计180秒合格观察；全部来源相对75°C危急线的原始未限幅预测余量至少5°C、速率不超过0.01°C/s，并受冻结的退出链2°C累计温升约束。稳定负载或普通温漂债务不单独否决这条退出路径，也不因此清除普通债务。真实确认新档后重新取证。退出边到10后仍保留其监测依据，不按普通工作目标减2°C立即升回。可归因实测风险触发精确原端点恢复；预测余量低于4°C预防恢复但不伪造热失败。完整边界及重启隔离见[高档逐级退出](thermal-policy.md#高档逐级退出)。每次普通下降仍需原有资格，手动合同、30秒实际下降间隔与失败低档记忆保持。高档单步退出绑定精确起终点及原执行截止，途中降低后不能借旧权限升回。可归因的失败下降允许精确恢复先前安全端点，包括高于10档；该保护不能变成通用高风权限。原八秒尝试间隔、持久预算和60秒执行截止保持。

当前候选不代表已部署。保护打断旧目的时保留终态证据，不伪造确认时间；到期未确认不能通过轮询不断创建新的六十秒截止时间。迟到的旧写入仍按真实读回处理，不复活旧操作。公开决策和历史区分normal、observing、empirical、recovering、critical、expired、degraded，并保留有界来源及观察证据。未知旧记录不补推断。离线检查、原生检查与当前实机版本分别报告，候选检查结果以统一入口check.py生成的报告为准。

下降边的自动或手动来源在原请求时确定，确认或热失败前切换设置不能改变该来源。物理档位确认与当前散热需求分别处理，确认帧出现可信危急温度时仍在同一轮计算保护，不先返回低档确认。名称缺失、空白、null或格式不合格不构成新设备身份；保留原失败工况并暂停普通下降观察，直到完整身份恢复，温度保护不因缺少这项元数据而失效。

现有 Docker 入口标识仍为 `docker-completed-execution-r1-20261015`，镜像标签为 `dgx-thermal-control:completed-execution-r1-20261015`；这是部署入口的名称，不证明当前工作区修改已构建或发布。候选内容以确切源码清单及其 SHA256 区分。离线统一检查、确切 ARM64 镜像检查和实际运行核对分别记录。候选源码本身不证明已部署或实机通过。失败保留新版、学习状态和故障证据，修复后向前发布，不自动回滚。

`Controller.feedback_matches_request` 使用原始操作与执行周期判断当前读回归属，服务仅判断设备物理健康。已完成且目的档不同的历史操作不再绑定当前反馈，包括高风授权撤回后的旧高档记录。历史状态和原因保留。仍待执行的周期继续要求目的档匹配、读回严格晚于本次目的请求时间，并遵守原截止时间。同目的已完成记录仍拒绝旧回执。未知或格式异常的执行记录不授予确认，状态查询不改变操作生命周期。

### 有界日志暂态容错

J-01仅部分修复。`Journal.prune` 保留单次两秒预算、索引验证和第二次完整盘点。若两次原始路径集合一致、原始身份仍匹配认证记录、所有下界均在本次保留期内、各配对索引长度仍与第二次盘点一致，且包含索引及工作文件的占用满足本次预留容量，完成原有孤立文件检查及最终预算核验后可返回0，不再执行两次无变化的重复盘点。不缓存跨次目录准入，不把未完成维护当作成功。需要删改的路径保持原有最终容量检查与同步合同。

首次扫描本身超时、冷索引验证和大量删改的进展问题仍未解决。历史失败复现与跨次证据权限分析保留在 `.audit/convergence-r2/journal_known_failure.py`、`journal-judgment.md`，其中无变化重复扫描用例应由新回归覆盖，首次扫描用例仍是已知限制。离线通过不证明当前文件集合的实际维护能及时完成；上线须另读连续写入、清理错误及真实风机反馈。没有延长存储宽限、重试未知提交或放宽完整性验证。

正式容器 CPU 配额为1.0。0.5配额下，采集、控制和日志维护共享进程预算，实测出现CPU限流及反复清理超时；只读独立清理样本不代表整个服务的预算。提高配额不改变三秒采样、两秒清理截止、保留期、容量、电机间隔或温度保护，也不保证首次扫描和任意规模目录均能完成。实际运行仍须分别核对清理错误、连续写入和下降信用，不能用镜像测试通过替代。

仅追加前准备或清理阶段、确定尚未提交的 TimeoutError 或 EAGAIN/EBUSY/EINTR/ETIMEDOUT 可暂停下降而保持当前新鲜正转速匹配档。必须同时具备本次完整安全温度证据，不能借用通信宽限；设置任务、电机债务和未知读回不授予宽限。首次失败起九秒或第三次连续失败立即升级保护，状态查询与一次写入成功不能续期。温度上调和危急保护始终有效。

追加阶段提交结果未知、追加后的异常、磁盘满、权限、完整性及未知异常立即保护。失败行不重试。已追加成功的计数保留，未知提交不冒称丢弃，公开 storage_health 保留安全的异常类别、errno、阶段、提交确定性与时间，不公开异常内容或路径。队列溢出仍立即保护。

R4候选将存储恢复与短暂维持风机的资格分开。软宽限和硬存储故障均须两个正常新行完成清理、可靠追加及最终占用核算，成功发布的完成证据至少相隔三秒，且属于同一已核实的当前设置版本。设置任务未完成、设置错误、版本或设置内容变化、追加或后处理失败均不授予恢复；两次不同版本不能合并。每次故障推进内部故障代数，写入派发后若又发生队列或设置维护故障，旧写入返回不能清除新故障或重置其恢复计数。原九秒软宽限、第三次连续失败和硬错误保护不变，失败行不重试。

存储健康可以在风机仍为请求10、实际16、pending时恢复，不伪造设备匹配，也不要求先完成被保护冻结的下降。它只解除存储这一项阻塞，不解除温度、传感器、真实反馈、电机预算、持久意图或热记忆门控，不积累下降信用，也不发送设备指令。短暂维持风机仍须上段完整温度和匹配反馈资格。恢复后重新取得相应下降窗口，不能把存储恢复当作风机已经降档。原清理两秒预算和J-01首次扫描限制不变，没有新增或重启实机验收。

上述 StorageHealth 有界协议只用于默认生产固定规则模式。显式学习或关闭高风门控的旧兼容测试路径保留原有失败立即保护、下一次正常写入解除存储错误的合同；生产命令行不启用这些兼容模式。提交确定性计数仍在所有模式中保持真实。
